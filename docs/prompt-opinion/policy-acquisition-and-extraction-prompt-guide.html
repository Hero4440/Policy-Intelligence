Policy Acquisition And Extraction Prompt Guide

This page preserves the full guidance for scraping, downloading, searching, extracting, and validating payer policy documents so they match this project’s actual schema and stored policy examples.

Recommended Workflow

Yes. For this project, the best workflow is not “ask ChatGPT to invent policy JSON.” It should be:

  1. find/download the payer PDF
  2. extract clean text from the PDF
  3. ask Claude/ChatGPT to convert that text into your project’s schema
  4. validate and lightly review before saving

What your policies need to look like is defined by data/schemas/policy.schema.ts, and good examples are in data/policies/structured/aetna-upadacitinib-ra.json and data/policies/structured/uhc-adalimumab-ra.json.

What To Specify So Extracted Policies Match This Project

  • id: stable slug like uhc-adalimumab-ra
  • payer: must currently be one of UHC, Aetna, Cigna, BCBS-NC
  • plan: usually Commercial
  • policyTitle
  • drug.brandName
  • drug.genericName
  • drug.aliases
  • indication
  • optional indications
  • coverageStatus: covered, covered-with-pa, or excluded
  • paRequired: boolean
  • diagnosisRequirements[]
  • stepTherapy[]
  • otherRequirements[]
  • every requirement needs:
    • evidenceText
    • source.document
    • source.page
    • source.section
  • sourceDocument.filename
  • optional sourceDocument.url
  • sourceDocument.retrievalDate
  • optional sourceDocument.effectiveDate

Two Important Constraints

  • Your schema currently only accepts 4 payers. If you want more payers, update the schema first.
  • Evidence should be lightly summarized, but still traceable to the exact source section/page.

Recommended Prompt For Policy Discovery

Use this when you want Claude/ChatGPT to help you find candidate public policy PDFs:

Policy Discovery Prompt
I am collecting public US payer medical benefit drug policy PDFs for normalization into a structured policy database.

Find official public payer policy documents for:
- payer: [PAYER NAME]
- drug or generic: [DRUG]
- indication: [INDICATION if known]

Return only likely official source links, prioritizing payer/provider domains and PDF policy documents.
For each result, give:
1. title
2. URL
3. whether it looks like an official policy PDF
4. likely payer
5. likely drug/generic
6. why it matches

Do not invent links. If unsure, say unsure.

Recommended Prompt For Structured Extraction

Use this after you already have the PDF text:

Structured Extraction Prompt
Convert the following payer medical drug policy text into STRICT JSON matching this schema.

Requirements:
- Output valid JSON only. No markdown.
- Do not invent facts not supported by the text.
- If something is unclear, leave arrays empty or mark ambiguous true where appropriate.
- Preserve evidence grounding.
- Every diagnosis requirement, step therapy requirement, and other requirement must include:
  - evidenceText
  - source.document
  - source.page
  - source.section
- Keep evidenceText short and faithful to the policy.
- Use these enums exactly:
  - payer: UHC | Aetna | Cigna | BCBS-NC
  - coverageStatus: covered | covered-with-pa | excluded
  - tier: preferred | non-preferred
- If multiple indications are present, put the primary one in indication and the full list in indications.

Schema shape:
{
  "id": "string",
  "payer": "UHC | Aetna | Cigna | BCBS-NC",
  "plan": "string",
  "policyTitle": "string",
  "drug": {
    "brandName": "string",
    "genericName": "string",
    "aliases": ["string"],
    "products": [
      {
        "name": "string",
        "tier": "preferred | non-preferred",
        "aliases": ["string"]
      }
    ]
  },
  "indication": "string",
  "indications": ["string"],
  "coverageStatus": "covered | covered-with-pa | excluded",
  "paRequired": true,
  "diagnosisRequirements": [
    {
      "icd10Codes": ["string"],
      "description": "string",
      "evidenceText": "string",
      "source": {
        "document": "string",
        "page": 0,
        "section": "string"
      }
    }
  ],
  "stepTherapy": [
    {
      "drugName": "string",
      "dosage": "string",
      "duration": "string",
      "failureCriteria": "string",
      "evidenceText": "string",
      "source": {
        "document": "string",
        "page": 0,
        "section": "string"
      }
    }
  ],
  "otherRequirements": [
    {
      "category": "string",
      "requirement": "string",
      "evidenceText": "string",
      "source": {
        "document": "string",
        "page": 0,
        "section": "string"
      },
      "ambiguous": false
    }
  ],
  "sourceDocument": {
    "filename": "string",
    "url": "string",
    "retrievalDate": "YYYY-MM-DD",
    "effectiveDate": "YYYY-MM-DD"
  }
}

Additional extraction rules:
- If the policy says prior authorization is required, set paRequired true.
- If any PA criteria exist, coverageStatus should usually be covered-with-pa unless the policy clearly says excluded.
- Put physician specialty rules, age rules, labs, site-of-care, combination restrictions, safety checks, dosing rules, and state-specific exceptions in otherRequirements.
- If step therapy is implied but not explicit, only include it if clearly supported by text.
- If ICD-10 codes are not present, use an empty array.
- Use a stable id like [payer]-[generic]-[short-indication-slug].

Here is the policy text:
[PASTE CLEAN PDF TEXT HERE]

Recommended Second-Pass Review Prompt

Use this after the first extraction:

Second-Pass Review Prompt
Review this extracted policy JSON against the source text.

Check for:
1. invented facts
2. missing major requirements
3. wrong coverageStatus
4. wrong paRequired value
5. unsupported step therapy entries
6. missing evidence/source.page/source.section
7. bad indication normalization
8. weak or inconsistent id naming

Return:
- corrected JSON only if fixes are needed
- otherwise return EXACTLY: VALID
