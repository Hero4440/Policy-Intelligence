**Create `src/mcp/tools/get_policy_summary.ts`:**

Export `registerGetPolicySummary(server: McpServer)` following existing tool pattern.

Tool registration:
- Name: `'get_policy_summary'`
- Description: "Get a detailed structured summary of a single medical policy including all coverage criteria, prior authorization requirements, step therapy and fail-first logic, preferred vs non-preferred product tiers, covered indications, and evidence citations from source documents. Use this when a user asks about specific requirements for a drug under a particular payer, or wants to understand a policy's full criteria. Identify the policy by its ID, or by providing both payer name and drug name."
- inputSchema: `policySummaryInput.shape` (from tool_inputs.ts, created in Plan 01)

Handler:
1. Resolve policy: if `policy_id` provided, find by ID in `getAllPolicies()`. If `payer` and `drug` provided, normalize drug via `normalizeDrugName(drug)` then use `findPolicy(payer, normalized)`. Per user decision: support both lookup methods.
2. If not found: return `buildErrorResponse()` with message, available_payers, available_drugs, and hint "Use list_policies tool to see all available policies".
3. If neither policy_id nor (payer+drug) provided: return `buildErrorResponse()` with message "Must provide either policy_id OR both payer and drug params".
4. Build structured_result with these fields (per user decision: inline evidence references):
   ```typescript
   {
     policy_id: policy.id,
     payer: policy.payer,
     plan: policy.plan,
     policy_title: policy.policyTitle || policy.sourceDocument.filename,
     effective_date: policy.sourceDocument.effectiveDate,
     drug: {
       generic_name: policy.drug.genericName,
       brand_name: policy.drug.brandName,
       products: (policy.drug.products || []).map(p => ({
         name: p.name,
         tier: p.tier,
         aliases: p.aliases
       })),
       preferred_products: (policy.drug.products || []).filter(p => p.tier === 'preferred').map(p => p.name),
       non_preferred_products: (policy.drug.products || []).filter(p => p.tier === 'non-preferred').map(p => p.name)
     },
     coverage: {
       status: policy.coverageStatus,
       prior_auth_required: policy.paRequired,
       indications: policy.indications || [policy.indication]
     },
     requirements: {
       diagnosis: policy.diagnosisRequirements.map(d => ({
         icd10_codes: d.icd10Codes,
         description: d.description,
         evidence_ref: 'diagnosis_requirements'  // inline ref per user decision
       })),
       step_therapy: policy.stepTherapy.map(s => ({
         prior_drug: s.drugName,
         dosage: s.dosage,
         duration: s.duration,
         failure_criteria: s.failureCriteria,
         evidence_ref: 'step_therapy'
       })),
       other: policy.otherRequirements.map(r => ({
         category: r.category,
         requirement: r.requirement,
         ambiguous: r.ambiguous,
         evidence_ref: r.category
       }))
     },
     source_document: {
       filename: policy.sourceDocument.filename,
       url: policy.sourceDocument.url,
       retrieval_date: policy.sourceDocument.retrievalDate,
       effective_date: policy.sourceDocument.effectiveDate
     }
   }
   ```
5. Extract evidence via `extractEvidenceArray(policy)` from evidence_formatter.
6. Calculate confidence via `calculateConfidence(policy)`.
7. Build human-readable answer (2-3 sentences): "{payer} {drug} policy ({coverageStatus}). {paRequired ? 'Prior authorization required.' : 'No prior auth.'} {stepTherapy.length > 0 ? 'Step therapy: must try {first step drug} first.' : ''} {products.preferred.length} preferred, {products.nonPreferred.length} non-preferred products. {indications.length} covered indications."
8. Return via `buildStandardResponse(answer, structured_result, evidence, confidence)`.

**Create `src/mcp/tools/compare_drug_across_payers.ts`:**

Export `registerCompareDrug(server: McpServer)` following existing tool pattern.

Tool registration:
- Name: `'compare_drug_across_payers'`
- Description: "Compare coverage policies for the same drug family across different health insurance payers. Returns a side-by-side comparison showing preferred vs non-preferred products, prior authorization requirements, step therapy logic, covered indications, and key differences highlighted. Includes a plain-language summary of the most important difference. Use this when a user asks how coverage differs between payers for a specific drug, or wants to compare plans."
- inputSchema: `compareDrugInput.shape` (from tool_inputs.ts)

Handler:
1. Normalize drug_family via `normalizeDrugName(params.drug_family)`.
2. Find all policies via `findPoliciesByDrug(normalized)`.
3. If zero policies: return `buildErrorResponse()` with available_drugs list and hint.
4. If only 1 policy: still build comparison but set confidence to 'MEDIUM' and add note in answer: "Only 1 payer has a loaded policy for {drug}. Add more policies to enable full comparison." Per user decision: show available data + mark missing.
5. Build comparison object — for each of these fields, create per-payer values and detect differences:

   a. **preferred_products**: For each policy, extract `policy.drug.products?.filter(p => p.tier === 'preferred').map(p => p.name) || []`. Set `differs: true` if values differ across payers. Extract evidence from otherRequirements where category matches 'preferred product requirement' or similar.

   b. **non_preferred_products**: Same pattern with tier === 'non-preferred'.

   c. **prior_auth_required**: Extract `policy.paRequired` per payer. Detect difference.

   d. **step_therapy**: Extract `policy.stepTherapy.map(s => ({ prior_drug: s.drugName, duration: s.duration, failure_criteria: s.failureCriteria }))`. Detect difference. Extract evidence from stepTherapy[0].evidenceText.

   e. **indications**: Extract `policy.indications || [policy.indication]` per payer. Detect difference.

   f. **coverage_status**: Extract `policy.coverageStatus` per payer.

   Each field in comparison: `{ values: Record<payer, value>, differs: boolean, evidence: Record<payer, EvidenceItem> }`.

6. **Generate key_differences array** — per user decision, prioritize coverage criteria:
   - If preferred_products differs: "Preferred biosimilar tiers: {payer} designates {products} as preferred"
   - If step_therapy differs: "Step therapy varies: {payer} requires {description}"
   - If prior_auth_required differs: "Prior authorization: {payer} requires PA, {other} does not"
   - Be specific with drug and payer names, not generic.

7. **Generate key_takeaway** (1-2 sentences, per user decision):
   - Check preferred_products first (highest priority per user decision)
   - For bevacizumab: "BCBS-NC designates Mvasi and Zirabev as preferred bevacizumab biosimilars, requiring documented trial and failure of all preferred products before non-preferred access. This creates a significant difference in product access pathways compared to other loaded payers."
   - For rituximab: "Cigna requires trial of all three rituximab biosimilars (Truxima, Riabni, Ruxience) before brand Rituxan access, an unusually restrictive step therapy compared to typical single-biosimilar-trial requirements."
   - Fallback for unknown drugs: generate from first detected difference.

8. Flatten all per-payer evidence into a single evidence array for the response.
9. Confidence: 'HIGH' if 2+ payers, 'MEDIUM' if only 1 payer.
10. Human-readable answer (3-4 sentences): "Compared {drug} coverage across {N} payers: {payer list}. {key_differences count} key differences found. {key_takeaway}"
11. Return via `buildStandardResponse(answer, { drug_family, payers_compared, comparison, key_differences, key_takeaway }, evidence, confidence)`.

Imports for both files: McpServer, schemas from tool_inputs.js, getAllPolicies/findPolicy/findPoliciesByDrug from loader.js, normalizeDrugName from drug-aliases.js, buildStandardResponse/buildErrorResponse from response_builder.js, extractEvidenceArray/calculateConfidence from evidence_formatter.js.
