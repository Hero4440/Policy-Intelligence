Using the extracted text from Task 1 and the PolicyRecordSchema from Plan 01, create 5 structured policy JSON files. Read each extracted text file carefully and map policy content to the schema fields.

**Target policy records (5 total across 3 payers, 4 drugs):**

1. **uhc-adalimumab-ra.json** — UHC Humira/adalimumab for RA
   - Expected: covered-with-pa, step therapy requiring methotrexate failure

2. **uhc-etanercept-ra.json** — UHC Enbrel/etanercept for RA
   - Expected: covered-with-pa, similar step therapy requirements

3. **aetna-adalimumab-ra.json** — Aetna Humira/adalimumab for RA
   - Expected: covered-with-pa, may have different step therapy details than UHC

4. **cigna-infliximab-ra.json** — Cigna Remicade/infliximab for RA
   - Expected: covered-with-pa for IV infusion, may require specialist administration

5. **aetna-upadacitinib-ra.json** — Aetna Rinvoq/upadacitinib for RA
   - This is the JAK inhibitor — check if Aetna has stricter requirements or exclusion for this newer drug class. If Aetna excludes or heavily restricts JAK inhibitors, this becomes the denial scenario. If not, adjust which policy serves as the denial/restriction scenario.

**For each policy record, extract and structure:**

- **payer/plan**: Identify payer and plan type from document header
- **drug**: Brand name, generic name, set aliases from drug-aliases.ts
- **indication**: "Rheumatoid Arthritis"
- **coverageStatus**: Determine from policy text — "covered", "covered-with-pa", or "excluded"
- **paRequired**: true/false
- **diagnosisRequirements**:
  - Extract ICD-10 codes (M05.*, M06.* typical for RA)
  - Include description and evidence text quote (1-2 key sentences)
  - Source attribution: document filename, page number, section header
- **stepTherapy**: For each required prior therapy:
  - Drug name (e.g., "methotrexate")
  - Dosage if specified (e.g., "15mg weekly")
  - Duration (e.g., "3 months")
  - Failure criteria (e.g., "inadequate response or documented intolerance")
  - Evidence text: the actual policy sentence(s) stating this requirement
  - Source: document, page, section
- **otherRequirements**: Lab requirements, prescriber qualifications, age restrictions, etc.
  - Set `ambiguous: true` for language like "may require", "in some cases", "at plan discretion"
  - Capture quantity limits and dosing restrictions in evidence text only (per locked decision)
- **sourceDocument**: PDF filename, URL (if available), retrieval date (today's date)

**Evidence text guidelines (per locked decisions):**
- Lightly edit policy quotes: fix PDF formatting artifacts but preserve substance
- Key sentences only (1-2 most relevant sentences per criterion)
- Full source attribution on every quote
- Do NOT fabricate or paraphrase — use real policy language

**Demo scenario mapping:**
- Let scenarios emerge naturally from real policy data
- Ensure at least one record enables the gap identification demo (patient almost meets criteria but missing one thing)
- Ensure at least one record enables a denial scenario
- If real policies don't naturally produce a denial, the JAK inhibitor (Rinvoq) with its stricter requirements may serve as the "heavily restricted" scenario
