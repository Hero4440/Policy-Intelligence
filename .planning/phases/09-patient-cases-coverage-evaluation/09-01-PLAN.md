<task type="auto">
  <name>Task 1: Expand patient-case storage model for Phase 9 intake</name>
  <files>src/storage/types.ts, src/storage/patient-store.ts</files>
  <action>
    Upgrade the patient-case types and persistence so the backend can support a real case workflow.

    Required changes:
    - preserve the existing `PatientCase.status` values, but make status derivation explicit and deterministic
    - ensure every stored document record includes:
      - `documentId`
      - `fileName`
      - `documentType`
      - `contentType`
      - `storedAt`
      - `summary`
      - `factCount`
    - support the document types named in the requirement where practical:
      - `clinical_note`
      - `prior_treatment_history`
      - `lab_results`
      - `referral`
      - `medication_order`
      - `denial_letter`
      - plus a safe fallback `uploaded_document`
    - keep documents persisted under the case folder; do not introduce a database
    - maintain backward compatibility with legacy seed cases already on disk

    Status rules:
    - `missing-docs`: no uploaded documents or no extracted facts yet
    - `ready-for-eval`: documents and facts exist but no completed evaluation is attached
    - `complete`: at least one saved evaluation exists for the case
  </action>
  <verify>
    `npx tsc --noEmit` passes.
    Creating a case then uploading one document writes a valid `case.json` plus stored document file under `data/patients/{case-id}/`.
  </verify>
  <done>
    Patient cases have a stable storage shape that supports Phase 9 intake and later evaluation status updates.
  </done>
</task>
