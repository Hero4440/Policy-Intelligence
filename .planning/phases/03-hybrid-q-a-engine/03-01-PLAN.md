**Entity extractor** — uses regex + existing `normalizeDrugName()` from `data/lookup/drug-aliases.ts`.

Export an `ExtractedEntities` interface:
```typescript
interface ExtractedEntities {
  drug?: string;       // Normalized generic name (e.g., "bevacizumab")
  payer?: string;      // Normalized payer name (e.g., "BCBS-NC")
  rawDrugs: string[];  // All normalized drug mentions
  rawPayers: string[]; // All detected payer mentions
}
```

Export `extractEntities(question: string): ExtractedEntities`:
- Drug detection: regex patterns for all drugs in drug-aliases.ts (bevacizumab family, rituximab family, adalimumab, etanercept, infliximab, upadacitinib) including brand names, biosimilars, and FDA suffix variants (bevacizumab-awwb, rituximab-abbs, etc.). Normalize each match via `normalizeDrugName()`.
- Payer detection: regex patterns for known payers: `bcbs[-\s]?nc|blue cross blue shield` -> "BCBS-NC", `cigna` -> "Cigna", `uhc|united\s*health` -> "UHC", `aetna` -> "Aetna".
- Case-insensitive matching throughout.
- Deduplicate normalized results.

Create `src/mcp/tools/utils/query_router.ts`:

**Query router** — pattern matching for deterministic pass-throughs, entity-based routing for LLM fallback.

Export a `RouteResult` interface:
```typescript
interface RouteResult {
  route: 'deterministic' | 'llm' | 'insufficient_evidence' | 'out_of_scope';
  toolName?: string;   // Phase 2 tool name for deterministic routes
  toolArgs?: Record<string, unknown>; // Args to pass to the Phase 2 tool
  reason?: string;     // Explanation for non-deterministic routes
}
```

Export `routeQuery(question: string, entities: ExtractedEntities): RouteResult`:

**Step 1 — Explicit pass-throughs** (per user decision):
- `/what policies (are|were) loaded|list.*policies|show.*policies/i` -> `list_policies` with optional payer/drug_family from entities
- `/summarize|summary of|what (does|are) .+ (require|cover)|tell me about .+ policy/i` -> `get_policy_summary` with payer+drug from entities (requires at least one entity)
- `/compare .+ across (payers|plans|insurers)|difference.*between .+ and/i` -> `compare_drug_across_payers` with drug_family from entities

**Step 2 — Out-of-scope detection**:
- If no drug AND no payer entities found, return `out_of_scope` with reason "No policy-related entities detected in question"

**Step 3 — Insufficient evidence pre-check**:
- If entities found but none match loaded policies (check via `getAllPolicies()`), return `insufficient_evidence` with reason listing loaded scope

**Step 4 — LLM fallback**:
- Return `route: 'llm'` — entities exist and match loaded policies, but question doesn't match deterministic patterns

For Step 1 tool args: populate `toolArgs` with the appropriate input shape for each Phase 2 tool (e.g., `{ payer, drug }` for get_policy_summary, `{ drug_family }` for compare_drug_across_payers).

Create `src/mcp/tools/utils/evidence_retriever.ts`:

**Evidence retriever** — filters policy evidence by detected entities and question keywords.

Export a `FilteredEvidence` interface:
```typescript
interface FilteredEvidence {
  items: EvidenceItem[];        // From response_builder.ts
  policies_searched: string[];  // Policy IDs that were searched
  match_count: number;
}
```

Export `retrieveEvidence(entities: ExtractedEntities, questionKeywords?: string[]): FilteredEvidence`:

1. Get all policies via `getAllPolicies()`.
2. Filter policies by entities:
   - If `entities.drug` set: match policies where `policy.drug.genericName` equals the normalized drug (case-insensitive)
   - If `entities.payer` set: match policies where `policy.payer` equals the payer (case-insensitive, handle BCBS-NC hyphen)
   - If both set: require both match
   - If neither set: return empty (caller should have caught this as out_of_scope)
3. Extract evidence from matching policies using `extractEvidenceArray()` from `src/mcp/utils/evidence_formatter.ts`.
4. If `questionKeywords` provided, further filter evidence items: keep items where `item.text` contains at least one keyword (case-insensitive). This is the "pre-filter by keywords" per user decision. If no keywords provided, return all evidence from matching policies.
5. Return the filtered evidence array, list of policy IDs searched, and match count.

Also export a helper `extractQuestionKeywords(question: string): string[]`:
- Remove stop words (the, a, an, is, are, does, do, what, which, how, for, in, of, to, and, or, with, by, from, about)
- Remove known entity words (drug names, payer names) — these are already used for policy filtering
- Return remaining words (lowercased) as keyword array
- Minimum 2 characters per word
