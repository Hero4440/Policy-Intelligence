<task type="auto">
  <name>Task 1: Create next-steps domain module</name>
  <files>src/server/next-steps.ts</files>
  <action>
Create `src/server/next-steps.ts` exporting a single async function `generateNextSteps(evalId: string): Promise<NextStepsPayload>`.

The function must:
1. Load the stored evaluation via `readEvaluation(evalId)` from `src/storage/evaluation-store.ts` — throw a typed error if not found.
2. Build `clinicNextSteps: string[]` — an ordered array of action strings derived deterministically from coverageStatus and checklist:
   - Always include "Review evaluation results with the clinical team"
   - If coverageStatus is "PA Required" or "Likely Eligible but Docs Missing": add "Submit prior authorization request to {payer}"
   - For each checklist item with status "MISSING": add "Obtain {item.criterion} documentation"
   - If coverageStatus is "Not Covered": add "Discuss alternative treatment options with prescriber"
   - If coverageStatus is "Preferred Alternative Required": add "Review preferred alternatives with prescriber before resubmission"
   - Always end with "Document all communications with payer in the case record"
3. Build `missingDocsList: MissingDocItem[]` — deterministic array from checklist items where status === "MISSING":
   - Each item: `{ criterion: string; category: string; rationale: string; policyEvidence: { snippet, document, page, section, fieldLabel } }`
   - Derive directly from `EvaluationChecklistItem.policyEvidence` — no LLM needed
4. Call the local Llama / Ollama API to generate `patientExplanation: string` — plain-language prose (2-3 paragraphs) explaining:
   - What the coverage decision means in plain English
   - What documents the clinic needs to collect
   - What the patient can expect next
   Use prompt: "You are a patient care coordinator. Given this coverage evaluation result, write a friendly 2-3 paragraph explanation for the patient. Coverage status: {coverageStatus}. Drug: {requestedDrug}. Payer: {payer}. Missing items: {missingDocsList.map(d => d.criterion).join(', ')}. Be empathetic and avoid medical jargon."
5. Call the local Llama / Ollama API to generate `payerAnalystBreakdown: PayerAnalystBreakdown` — structured object:
   - `summary: string` — 1-paragraph overview of which criteria apply
   - `criteriaAnalysis: Array<{ criterion, status, policyEvidence: { snippet, document, page, section }, clinicAction }>` — one entry per checklist item
   Use prompt: "You are a payer analyst. Given this coverage evaluation, write a concise clinical analyst narrative. For each criterion, note status and what evidence satisfies it. Respond in JSON with keys: summary (string), criteriaAnalysis (array of {criterion, status, policyEvidence: {snippet, document, page, section}, clinicAction}). Evaluation: {JSON.stringify(evaluation)}"
   Parse the JSON response; wrap in try/catch — if parse fails, use fallback object with summary from a second local Llama call (text only) and criteriaAnalysis mapped directly from checklist.

Use the existing local Ollama-compatible Llama path already used elsewhere in the repo. Respect `OLLAMA_URL` plus `LOCAL_LLM_MODEL` or `OLLAMA_MODEL`. Do not use Anthropic SDK or Claude for the active implementation.

Export types: `NextStepsPayload`, `MissingDocItem`, `PayerAnalystBreakdown`.
