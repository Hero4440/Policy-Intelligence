    2. Create `src/mcp/fhir/types.ts` with:
       - `ExtractedPatientData` interface: { diagnoses: ExtractedDiagnosis[], medications: ExtractedMedication[], coverage: ExtractedCoverage | null }
       - `ExtractedDiagnosis`: { code: string, system: string, display: string }
       - `ExtractedMedication`: { name: string, normalizedName: string, status: string, dateWritten?: string }
       - `ExtractedCoverage`: { payerName: string, planName?: string, status: string }
       - `FhirToken` type: { fhir_token: string, patient_id: string, fhir_server_url?: string }

    3. Create `src/mcp/fhir/client.ts` with:
       - `createFhirClient(baseUrl: string, bearerToken: string)` -- returns fhir-kit-client Client instance with Authorization header
       - `fetchPatientBundle(client, patientId)` -- calls Patient/{id}/$everything, follows pagination via bundle.link[rel="next"], returns merged bundle with all entries
       - `extractFhirToken(patientContext: Record<string, any>)` -- flexible token extraction: checks patient_context.fhir_token, patient_context.access_token, patient_context.token (returns FhirToken or null with clear error)
       - Default FHIR server URL from env: `process.env.FHIR_SERVER_URL || 'https://fhir.promptopinion.ai'`

    4. Create `src/mcp/fhir/extractors.ts` with:
       - `extractPatientData(bundle): ExtractedPatientData` -- orchestrator that calls individual extractors
       - `extractDiagnoses(bundle)` -- filters entries for resourceType 'Condition', extracts ICD-10 codes from code.coding (check ALL ICD-10 system URIs: 'http://hl7.org/fhir/sid/icd-10', 'http://hl7.org/fhir/sid/icd-10-cm', 'http://www.cms.gov/Medicare/Coding/ICD10'). Use defensive optional chaining throughout. Return { code, system, display } array.
       - `extractMedications(bundle)` -- filters for 'MedicationRequest' and 'MedicationStatement', extracts medication name from medicationCodeableConcept.coding (prefer RxNorm display, fallback to any coding.display). Normalize each name via `normalizeDrugName()` from drug-aliases.ts. Return { name, normalizedName, status, dateWritten } array.
       - `extractCoverage(bundle)` -- filters for 'Coverage' resource, extracts payor display name and plan info. Return single ExtractedCoverage or null.
       - All extractors MUST use defensive null handling: if (!resource?.field?.subfield) return empty/null. Never throw on missing FHIR data.

<task type="auto">
  <name>Task 2: Create criteria matching logic with cautious clinical language</name>
  <files>
    src/mcp/matching/language.ts
    src/mcp/matching/criteria_matcher.ts
  </files>
  <action>
    1. Create `src/mcp/matching/language.ts` with:
       - `ClinicalStatus` enum/const: 'appears_to_match' | 'may_be_missing' | 'documentation_may_be_needed' | 'unable_to_verify'
       - `ClinicalLanguage` object with helper functions:
         - `matched(criterion)` returns "Appears to match: {criterion}"
         - `missing(criterion)` returns "May be missing: {criterion}"
         - `needsDoc(criterion)` returns "Documentation may be needed: {criterion}"
         - `unverifiable(criterion)` returns "Unable to verify: {criterion}"
       - `DISCLAIMER` constant: "This analysis is based on automated extraction of available patient data and should be verified by a qualified clinician. Clinical judgment is required for final prior authorization determination."

    2. Create `src/mcp/matching/criteria_matcher.ts` with:
       - Import PolicyRecord from policy.schema, ExtractedPatientData from fhir/types, ClinicalLanguage from language
       - `CriterionResult` interface: { criterion: string, category: string, status: ClinicalStatus, message: string, evidence: string, source: SourceRef, matched_data?: any, is_ambiguous?: boolean }
       - `matchPatientAgainstPolicy(patientData: ExtractedPatientData, policy: PolicyRecord): CriterionResult[]` -- orchestrator that calls individual matchers below and returns flat array

       - `matchDiagnosisRequirements(diagnoses, diagnosisReqs)`:
         - For each DiagnosisReq, check if any patient ICD-10 code matches the required codes
         - ICD-10 matching MUST handle wildcards: policy codes like "M05.*" should match patient codes like "M05.79", "M05.811" etc. Implement prefix matching: strip ".*" from policy code, check if patient code starts with that prefix.
         - If match found: status='appears_to_match', include matched codes in matched_data
         - If no diagnoses at all: status='unable_to_verify' (no data to check)
         - If diagnoses exist but none match: status='may_be_missing'

       - `matchStepTherapyRequirements(medications, stepTherapyReqs)`:
         - For each StepTherapy requirement, check if patient has a medication matching the required drug name
         - Use normalizeDrugName() on both sides for comparison
         - Handle multi-drug requirements (e.g., "methotrexate, leflunomide, sulfasalazine, or hydroxychloroquine") -- split by comma/or and check if ANY match
         - If match: status='appears_to_match', note: cannot verify duration/dosage from FHIR data alone so add caveat in message
         - If no match: status='may_be_missing'
         - If no medications at all: status='unable_to_verify'

       - `matchOtherRequirements(patientData, otherReqs)`:
         - For most "other" categories (prescriber qualification, combination therapy, safety screening), status='documentation_may_be_needed' -- these typically require clinical chart review, not FHIR data
         - If category is 'lab monitoring' and ambiguous flag is false, status='documentation_may_be_needed' (labs might be in Observations but we don't parse those yet)
         - Always preserve evidence text and source from policy
  </action>
