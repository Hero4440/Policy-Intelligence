  <name>Task 1: Update tool schema and rewrite check_patient_readiness with FHIR integration</name>
  <files>
    src/mcp/schemas/tool_inputs.ts
    src/mcp/tools/check_patient_readiness.ts
  </files>
  <action>
    1. Update `src/mcp/schemas/tool_inputs.ts`:
       - Update patientReadinessInput.patient_context to accept optional FHIR token fields:
         ```
         patient_context: z.object({
           fhir_token: z.string().optional().describe("FHIR bearer token from Prompt Opinion SHARP extension"),
           patient_id: z.string().optional().describe("FHIR Patient resource ID"),
           fhir_server_url: z.string().optional().describe("FHIR server base URL (defaults to env FHIR_SERVER_URL)")
         }).passthrough().describe("Patient clinical context. Include fhir_token and patient_id for automated readiness analysis. Without them, returns criteria checklist only.")
         ```

    2. Rewrite `src/mcp/tools/check_patient_readiness.ts`:
       - Keep: drug normalization, policy lookup, error handling with available payers/drugs (from Phase 2)
       - Add imports: extractFhirToken, createFhirClient, fetchPatientBundle from fhir/client; extractPatientData from fhir/extractors; matchPatientAgainstPolicy from matching/criteria_matcher; DISCLAIMER from matching/language

       - **New flow (two modes):**

       **Mode A: With FHIR token** (patient_context has fhir_token + patient_id):
       a. Extract token via extractFhirToken(patient_context)
       b. Create FHIR client with token
       c. Fetch patient bundle via fetchPatientBundle
       d. Extract patient data via extractPatientData
       e. Match against policy via matchPatientAgainstPolicy
       f. Build response with:
          - readiness_summary: { criteria_met (count), criteria_possibly_missing (count), criteria_needing_documentation (count), total_criteria }
          - overall_assessment: cautious summary string (all met = "All criteria appear to be met based on available data", some missing = "Some criteria may require additional documentation or may not be met")
          - criteria_details: the CriterionResult[] array
          - patient_data_summary: { diagnoses_found: N, medications_found: N, coverage_found: boolean }
          - disclaimer: DISCLAIMER constant
          - source: policy source info

       **Mode B: Without FHIR token** (no fhir_token or patient_id):
       - Fall back to Phase 2 behavior: return criteria checklist with status 'requires_patient_data'
       - Add note: "Provide fhir_token and patient_id in patient_context for automated readiness analysis"

       **Error handling for FHIR failures:**
       - If FHIR server returns error (401, 404, network error), catch it and return:
         - The criteria checklist (Mode B fallback) PLUS
         - An fhir_error field: { message: "Failed to retrieve patient data: {error}", suggestion: "Verify FHIR token is valid and patient_id exists" }
         - readiness_status: 'fhir_error_fallback'
       - Do NOT let FHIR errors crash the tool -- always return useful policy criteria

    3. Update tool description string to reflect FHIR capability:
       - Remove "Note: Full patient context integration via FHIR is coming in a future update"
       - Add: "When patient_context includes fhir_token and patient_id, retrieves patient FHIR data and performs automated readiness analysis. Without FHIR context, returns the criteria checklist for manual review."
  </action>
  <verify>
    Run `npx tsc --noEmit` -- should compile with zero errors.

    Grep for "DISCLAIMER" import to confirm disclaimer is included.
    Verify no definitive language: grep -i "meets criteria\|does not qualify\|qualifies\|approved\|denied" should find nothing.
  </verify>
