<task type="auto">
  <name>Task 1: Implement startup disk scan and index rebuild</name>
  <files>src/storage/startup.ts</files>
  <action>
    Create `src/storage/startup.ts`. This module is the authoritative startup routine for the storage layer.

    **In-memory cache**: Maintain a module-level `Map<string, PolicyRecord>` keyed by policyId (current version only). This is the in-memory policy cache.

    ```ts
    const policyCache = new Map<string, PolicyRecord>();
    ```

    **loadStorageOnStartup(): void** (synchronous — runs before server starts accepting requests):
    1. Call `ensureDataDirectories()` from `./paths.js`.
    2. Scan `POLICIES_STRUCTURED_DIR` using `readdirSync`. Filter files matching pattern `/^(.+)_v(\d+)\.json$/` (versioned policy files — exclude diff files).
    3. For each matching file:
       a. Read and JSON.parse the file content.
       b. If parse fails: `console.error('[startup] skipping malformed file:', fileName, err.message)` — continue to next file.
       c. Extract `record` field (type `PolicyRecord`).
       d. Parse the version number from the filename suffix.
       e. Track the highest version per policyId.
    4. After scanning all files, for each policyId → latest version:
       a. Store `record` in `policyCache`.
    5. Rebuild `data/policies/index.json` from the scanned data:
       a. Build `PolicyIndexEntry` array from policyCache entries using `derivePolicyId`-derived data.
       b. Call `saveIndex` (reuse the atomic write pattern from policy-store.ts — or call a re-exported helper if one exists).
       c. Log: `console.error('[startup] index rebuilt:', N, 'policies')`.
    6. Log startup summary: `console.error('[startup] loaded:', policyCache.size, 'policies from disk')`.

    **getPoliciesFromMemory(): PolicyRecord[]**:
    - Return `[...policyCache.values()]`.

    **getPolicyFromMemory(policyId: string): PolicyRecord | undefined**:
    - Return `policyCache.get(policyId)`.

    **IMPORTANT**: Per CONTEXT.md — only policies are loaded into memory at startup. Patients and evaluations stay on disk and are read on demand (already implemented in plans 02-03).

    Import `PolicyRecord`, `PolicyIndex`, `PolicyIndexEntry` from `./types.js`.
    Import `POLICIES_STRUCTURED_DIR`, `POLICY_INDEX_PATH`, `ensureDataDirectories` from `./paths.js`.
    Import `derivePolicyId` from `./policy-store.js`.

    For the index rebuild, implement a local `rebuildAndSaveIndex(entries: PolicyIndexEntry[]): void` that writes atomically (temp + rename) — this avoids circular imports with policy-store.ts's `saveIndex` which is internal.
  </action>
