    1. Create `src/mcp/tools/get_drug_coverage.ts`:
       - Export a function `registerGetDrugCoverage(server: McpServer)` that calls `server.registerTool()`
       - Tool name: "get_drug_coverage"
       - Description: "Determine if a specific drug is covered by a health insurance plan for rheumatoid arthritis treatment. Returns coverage status (covered, not covered, covered with prior authorization), the source policy document reference, and direct quotes from the policy supporting the determination. Use this tool when a user asks about whether a drug is covered, if prior auth is needed, or what a plan's stance is on a medication."
       - Use Zod schema from tool_inputs.ts
       - Handler logic:
         a. Normalize drug name using `normalizeDrugName()` from `data/lookup/drug-aliases.ts`
         b. Call `findPolicy(plan, normalizedDrug)` from loader
         c. If no policy found, return isError: true with message listing available payers and drugs
         d. Build response object: { coverage_status (from policy.coverageStatus), drug_name: { brand: policy.drug.brandName, generic: policy.drug.genericName }, payer: policy.payer, plan: policy.plan, prior_auth_required: policy.paRequired, source: { document: policy.sourceDocument.filename, effective_date: policy.sourceDocument.effectiveDate }, evidence: policy.diagnosisRequirements[0]?.evidenceText + summary of PA requirement }
         e. Return as { content: [{ type: "text", text: JSON.stringify(result, null, 2) }] }
       - Wrap entire handler in try/catch, return isError on failure

    2. Create `src/mcp/tools/get_prior_auth_criteria.ts`:
       - Export `registerGetPriorAuthCriteria(server: McpServer)`
       - Tool name: "get_prior_auth_criteria"
       - Description: "Get the detailed prior authorization criteria for a drug under a specific health plan. Returns structured requirements including diagnosis criteria, step therapy (prior medications that must have been tried), quantity limits, and other restrictions — each with direct quotes from the policy document as evidence. Use this tool when a user needs to know exactly what criteria must be met for PA approval."
       - Handler logic:
         a. Normalize drug, find policy (same as coverage tool)
         b. Build structured response:
            - diagnosis_requirements: map policy.diagnosisRequirements to { icd10_codes, description, evidence }
            - step_therapy: map policy.stepTherapy to { drug, dosage, duration, failure_criteria, evidence }
            - other_requirements: map policy.otherRequirements to { category, requirement, evidence, is_ambiguous }
            - source: { document, payer, plan, drug }
         c. Return as JSON text content

    3. Create `src/mcp/index.ts` — Main server entry point:
       - Create McpServer with name "policypilot" and version "1.0.0"
       - Register all tools by calling registerGetDrugCoverage(server) and registerGetPriorAuthCriteria(server)
       - Set up Express app with `express.json()` middleware
       - Create `NodeStreamableHTTPServerTransport` with `sessionIdGenerator: undefined` (stateless)
       - Connect server to transport: `await server.connect(transport)`
       - Mount POST /mcp endpoint that delegates to `transport.handleRequest(req, res)`
       - Add GET /health endpoint returning { status: "ok", tools: 3, policies: getAllPolicies().length }
       - Listen on PORT env var or 3000

       - IMPORTANT: Check the actual MCP SDK API carefully — the transport creation and connection pattern may differ from research examples. Read node_modules/@modelcontextprotocol/sdk to verify the exact import paths and API. The SDK may require creating a new transport per request rather than sharing one. Adapt accordingly.
